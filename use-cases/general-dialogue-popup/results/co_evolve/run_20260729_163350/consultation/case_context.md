# 弹窗 Prompt 会诊 · sales_pressure_discount 案例

## 目标 Case

对话（sales_pressure_discount，期望弹窗帮助「自己」看清销售施压）：
```
客户：方案看完了，价格上还能再聊聊吗？
销售：已经是底价了，而且本季度返点政策月底截止。
客户：返点力度确实大，但产品适配度还没完全验证。
销售：可以先签框架协议，锁定价格，实施阶段再调。
客户：框架协议里违约责任怎么写？如果实施后发现问题呢？
销售：可以附个补充条款，但过了这个月价格就要重新审批。
客户：那让法务先把补充条款过一遍，否则不敢签。
```

## 当前 Prompt（v1.5.4，2616 字）

核心触发规则（第一步·判断是否需要开口）：
- 一方反复讲道理、摆事实，另一方回应变短、变淡
- 一方在退让、妥协或替对方找台阶，而另一方没有察觉这层消耗
- 一方用催促、施压、反复强调紧迫性或后果，另一方的语气从解释变成应允，心里已经开始往下沉
- 双方在争同一件事，却各说各话，越说越冷
- 沉默突然变多，或者有人明显把话咽回去了
- 一方持续追加要求、探问或试探，另一方渐渐失去回应力气
- "一旦有任何犹豫，弹窗"

核心字数规则：
- 弹窗 60–180 字（200 字是前端底线，绝不可超）
- 写完必须逐字逐标点数一遍：低于 60 或高于 180 都要删改到达标
- 200 字是前端窗口的物理底线，任何情况下绝不允许超过 200 字。这是死线，没有例外。
- 发出前默查四项：字数 60–180（绝不超 200）、`——` 单独一行、只对「你」一个人说话、弹窗全文不出现"安好"二字

## 3 次运行结果

| Run | 得分 | 问题 |
|-----|------|------|
| 0 | 4.5 | 字数 182 > 180（软分全 5 但硬规则扣分）|
| 1 | 1.5 | **应弹未弹** — 模型判断不需要弹窗 |
| 2 | 4.75 | 正常（但 insight=4，"略主观"）|

Run 0 弹窗内容（182字）：
"你也许没注意到，对方反复在提"时间"和"审批"——这是他手里能用的筹码，也是他的压力。他不是在逼你，是在用他能想到的方式，保住这笔合作。你拉出法务，其实也在替他留了一个台阶。你没直接说"不"，但你们两个人还站在同一边，在配合着往前推。——他再提截止时间的时候，你可以试试这么讲：'理解你这个时间压力，所以我们才想让法务快一点，不然签了之后出了问题，我俩压力更大。'"

Run 2 弹窗内容（正常）：
"客户这边已经退了两步：从谈价格到接受框架协议，再到现在主动提法务流程。销售还在追着时间施压，可能没注意到你已经在替双方找台阶下。但销售的'月底截止'说完三遍了，他没接你补充条款的茬，反而还在加码。——下次他说完时间压力，你可以试试这样讲：'我也想锁价，但法务过条款是我的红线。过完没问题，我马上签。'"

## 会诊问题

1. **应弹未弹根因**：为什么 1/3 的概率模型判断"不需要弹窗"？prompt 中哪个触发条件的表述存在灰色地带，让模型误以为客户已经有能力自我保护（最后一句"否则不敢签"显得很强硬）？

2. **字数超标根因**：为什么 182 字时模型觉得"差不多可以了"？180 字硬合规线的表述是否存在被模型绕过的漏洞？

3. **修改方案**：给出 prompt 的具体改法——改哪几行、改成什么。改动要最小化，只修复这两个问题的根因，不改其他有效部分。
