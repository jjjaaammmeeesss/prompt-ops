# v1.4 vs v1.8 场景适配说明

> 基于 v7 自进化 15 用例 × 2 版本完整评测 + 多轮横评原文对比。
> v1.7 已删除（脑补和事实错误严重）。

|---|---|---|

## v1.4 擅长场景

### 1. 直接冲突/高压对峙 ⭐⭐⭐

经理发火、客户投诉这类"对方情绪外显"的场景，v1.4 的简洁 prompt 让 LLM 有更多自由度去接住情绪。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| manager_anger | **0.967** | 0.900 | v1.4 不做"自查清单"，洞察更流畅 |
| customer_rage | **0.933** | 0.933 | 持平，都准确 |

**原因**：高压场景下，对话本身就是强信号，不需要复杂的"易误判场景"指引。v1.4 的简洁 prompt 反而让 LLM 不被 checklist 分心，能聚焦于"对方这句狠话底下到底在要什么"。

### 2. 明确的互动模式/循环 ⭐⭐⭐

追-逃、绕弯子这类模式清晰可见的场景，v1.4 的"看见模式"直觉很准。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| couple_chase_dodge | **0.967** | 0.933 | v1.4 抓住"认错退出压力"，建议可照搬 |
| roommate_unspoken | **0.967** | 0.867 | v1.4 抓"绕弯子"更直接 |

**原因**：v1.4 的默认行为就是"看见模式"，没有 v1.8 那样多层次的准确性约束——在这些模式显眼的场景里，不需要约束。

### 3. 情感浓度高的个人关系 ⭐⭐

朋友边界、旧友借钱这类"关系本身就有温度"的场景。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| old_friend_loan | 0.933 | **0.967** | 接近，v1.8 建议稍准 |
| friend_soft_boundary | 0.900 | **0.967** | v1.8 更精确，但 v1.4 有"模式不会自己停"的灵魂句 |

## v1.8 擅长场景

### 1. 隐性的边界丢失/温水煮青蛙 ⭐⭐⭐

这是 v1.8 最大的优势区——表面一团和气、实际"你"正在悄悄丢边界。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| colleague_hint | 0.000 | **0.900** | v1.4 判为健康对话→安好；v1.8 新增"3+1场景"正确开口 |
| sibling_rescue_loop | 0.767 | **0.933** | v1.8 更准确抓住"一磨就松手" |

**原因**：v1.8 prompt 专门加了"容易被误判成健康而放过的情况"——这正是 v1.4 把 colleague_hint 沉默的根因。v1.4 的"开口门槛宁高勿低"在这类场景上过于保守。

### 2. 需要精确确认说话者身份的场景 ⭐⭐⭐

对话里出现"婆婆""你""对方"等称谓混杂时，v1.8 的准确率显著更高。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| couple_push_retreat | 0.833 | **0.967** | v1.4 把伴侣当成"你"，严重张冠李戴 |
| teacher_care | 0.767 | **0.933** | v1.4 把老师当成"你"，视角反了 |
| mother_in_law_outburst | 0.800 | **0.867** | v1.4 替婆婆编造"怕家散"心理动机 |

**原因**：v1.8 prompt 有"先认出你是谁"的明确流程 + 性别/称谓中性化规则 + "别给对方编造原话没有的心理动机"。v1.4 在这些方面没有硬约束。

### 3. 高难度立场平衡场景 ⭐⭐

需要同时对"你"说实话又不让"你"觉得被审判时，v1.8 更稳。

| 用例 | v1.4 | v1.8 | 分析 |
|------|------|------|------|
| partner_unspoken_need | 0.900 | **0.933** | v1.8 避免了对"你"的评判味，建议更自然 |
| adult_child_weak | **0.867** | 0.833 | 接近，v1.4 略好 |

**原因**：v1.8 的"立场细化规则"（别把错全揽到你身上、描述模式时避免夹带评判措辞）在微妙场景里生效。

## 两者都不擅长的场景

### 安好类（两个版本都可能沉默）

| 用例 | v1.4 | v1.8 |
|------|------|------|
| neighbor_noise | 0.0 | 0.0 |
| online_friend_meetup | 0.0 | 0.0 |

`neighbor_noise` 是一段顺畅的邻里沟通，`online_friend_meetup` 是自然的网友见面。两个 prompt 的"安静时只回安好"规则都触发了，导致空输出。

**潜在问题**：v1.4 共 3 个 0 分案（colleague_hint 不应该沉默但它沉默了），v1.8 共 2 个 0 分案。v1.8 把 colleague_hint 救回来了，但两个版本都在真正的"健康对话"上正确沉默了——这些 0 分可能是正确的行为。

## 选用建议

```
场景特征                         推荐版本
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
对方情绪外显、直接冲突           v1.4（更有温度）
关系模式清晰可见（追逃、绕弯）   v1.4（直觉更准）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
表面和气、边界悄悄被侵蚀         v1.8（唯一选择）
称谓混杂、需确认说话者           v1.8（不会张冠李戴）
高压+微妙立场平衡               v1.8（更稳的分寸）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
安静时回"安好"的触发准确率       两者相同（都有误判空间）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 根因

v1.4 只有 80 行，规则少 = 自由度高 = 好 case 很出彩，坏 case（安好/张冠李戴/脑补）无法防御。

v1.8 有 100 行，多了三层防护（准确性细则、立场细化、易误判场景），坏 case 从 6 个降到 3 个——但代价是好 case 的"出彩感"被 Checklist 效应压平了。

**v1.4 的上限更高，下限更低。v1.8 把下限抬上来了，但略微压低了上限。** 最终选择取决于你的风险偏好：是更不能容忍一个 0 分，还是更不能容忍一个"合规但缺灵魂"的弹窗。
