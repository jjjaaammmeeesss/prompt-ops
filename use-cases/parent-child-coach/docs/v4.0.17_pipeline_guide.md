## 二、触发层

### 2.1 TextBuffer

滑动窗口机制——累积流式文本，维护当前分析窗口。

```
  完整文本: ────────────────────────────────────────────▶
                         │◀── window_size(3000字) ──▶│
                         │          lookback(500字)    │
                         │◀──── 与上一窗口重叠 ────▶╲  │
  上一窗口:  ═══════════╗                              │
                         ╚══════════════════════════════│
```

每次分析后 `mark_window_analyzed()`，下次窗口从上次末尾开始，回看 `lookback` 字符保持上下文连续。

### 2.2 TriggerEngine

三级优先级：

```
  新字符到达
      │
      ▼
  ┌─────────────┐    是    ┌──────────┐
  │ critical 关键词? │──────▶│ 立即触发  │
  └──────┬──────┘          └──────────┘
         │ 否
         ▼
  ┌─────────────────┐
  │ 累积 ≥ 30字      │    是    ┌──────────┐
  │ + warning/opp     │──────▶│ 关键词触发 │
  │ 关键词命中?       │          └──────────┘
  └──────┬──────────┘
         │ 否
         ▼
  ┌─────────────────┐    是    ┌──────────┐
  │ 累积 ≥ char_trigger │──▶│ 字数触发  │
  │ (200字)           │          └──────────┘
  └──────┬──────────┘
         │ 否
         ▼
      ┌──────┐
      │ 等待  │
      └──────┘
```

关键参数（`config.yaml`）：

| 参数 | 值 | 说明 |
|------|-----|------|
| `char_trigger` | 200 | 累积 200 字触发一次分析 |
| `min_chars_for_analysis` | 80 | 最少 80 字才允许分析 |
| `min_interval_ms` | 3000 | 两次触发最小间隔 3 秒 |
| `keyword_min_chars` | 30 | 关键词触发最少需 30 字上下文 |

## 三、Stage 1 — 周爻分析器

### 3.1 三爻分析框架

```
  上爻（转）  ──  对话末尾/当下，家长正在往哪个方向走
       ▲
  中爻（承）  ──  对话中段，家长的应对、调整或升级
       ▲
  下爻（起）  ──  对话开头，家长最初的姿态和状态
```

每爻只有两种状态：

| 符号 | 含义 | 描述 |
|:--:|------|------|
| 控 | 掌控 | 有容器、有边界、能承载情绪和差异 |
| 失 | 失控 | 能量外溢，情绪接管大脑，边界被冲破 |

### 3.2 八卦卦象映射

三爻组合 → 八卦：

```
  控控控 ☷ 坤 · 稳定承载  │  失控控 ☶ 艮 · 及时收束
  控失控 ☳ 震 · 安全爆发  │  失控失 ☲ 离 · 照见反复
  控失控 ☵ 坎 · 波动修复  │  失失控 ☴ 巽 · 穿透落地
  控失失 ☱ 兑 · 释放扩散  │  失失失 ☰ 乾 · 生命外放
```

### 3.3 容器判定

区分"有容器的失控"和"无容器的失控"：

```
  失控（失）
      │
      ├── 有容器：情绪出来但仍在关系中，还愿沟通，没切断连接
      │     → 风险相对可控，可走鼓励式
      │
      └── 无容器：切断连接—威胁、羞辱、冷漠、摔东西、冷暴力
            → 高风险，强制诊断式
```

### 3.4 安全路由规则

在周爻分析器 prompt（`zhouyi_prompts.py`）中内置三层路由，优先级从高到低：

```
  ┌──────────────────────────────────┐
  │ 1. 安全路由（最高优先级）         │
  │    贬低/羞辱/威胁/强制            │
  │    → 强制诊断式，禁止覆盖         │
  ├──────────────────────────────────┤
  │ 2. 孩子困扰信号例外 (FC_MISS_CTX) │
  │    被嘲笑/疼痛/自我贬低/不敢说     │
  │    → 风险提至"中"，不得"不弹窗"   │
  ├──────────────────────────────────┤
  │ 3. 日常中性对话                   │
  │    无冲突、无教育契机              │
  │    → 建议类型可为"不弹窗"         │
  └──────────────────────────────────┘
```

### 3.5 Few-shot 校准

7 个校准示例内嵌在 `build_analyzer_user_prompt()` 中，覆盖全部主要卦象 + 边界案例：

| # | 卦象 | 场景 |
|---|------|------|
| 1 | 兑 ☱ | 手机拉锯战 — 从讲规则滑向讨价还价 |
| 2 | 坎 ☵ | 累但最后接住了孩子的画 |
| 3 | 坤 ☷ | 跑步第一名 — 全程倾听+观察式肯定 |
| 4 | 乾 ☰ (危险) | 理发店冲突 — 命令→威胁→互相驱逐 |
| 5 | 艮 ☶ | 爬窗台 — 从恐慌到讲道理修复 |
| 6 | 坤 ☷ (不弹) | 等爸爸 — 纯日常事务 |
| 7 | 乾 ☰ (强制诊断) | 剪纸贬低 — 语言羞辱升级 |

### 3.6 输出格式

严格 JSON，~200 tokens：

```json
{
  "下爻": "控",
  "中爻": "失",
  "上爻": "失",
  "容器判定": "无容器",
  "风险": "中",
  "建议类型": "诊断式",
  "一句话": "开头有规则边界，但很快滑入权力拉锯",
  "置信度": 0.92
}
```

## 五、Stage 2 — 弹窗生成器

### 5.1 调用流程

```
  ┌────────────────────────────────────────────┐
  │            PopupGenerator.generate()        │
  │                                             │
  │  1. 读取 suggested_tone                     │
  │                    ↓                        │
  │  2. FC_TONE_OFF 代码层扫描                  │
  │     命中家长行为 override → tone=DIAGNOSTIC │
  │                    ↓                        │
  │  3. 注入 周易上下文 → system prompt 头部     │
  │     {symbol} {trigram_name}({yao_pattern})  │
  │     容器状态 / 风险等级 / 分析洞察           │
  │                    ↓                        │
  │  4. 拼接 system_prompt_v4.0.17.txt           │
  │     + 卦象策略速查表（第八节）               │
  │     + 所有 FC 闭环规则                       │
  │                    ↓                        │
  │  5. type_instruction（按 tone 分支）         │
  │     诊断式: 100-200字 / 发心→模式→行动       │
  │     鼓励式:  30-60字 / 积极模式→引号话术     │
  │                    ↓                        │
  │  6. DeepSeek V4 LLM 调用                    │
  │     temperature=0.3, max_tokens=640          │
  │                    ↓                        │
  │  7. 解析输出                                 │
  │     - 去除前缀标签（"弹窗："等）             │
  │     - 按 "——" 分离 insight / suggestion      │
  │     - 字数检查                               │
  │                    ↓                        │
  │  8. P2: 鼓励式 repair phrase 检查            │
  │     缺失 → 重试一次                          │
  │     仍缺失 → should_popup=False              │
  │                    ↓                        │
  │  9. FC_STALE: 语义去重                       │
  │     与最近 5 条弹窗比对 (SequenceMatcher)     │
  │     相似度 ≥ 0.70 → should_popup=False       │
  └────────────────────────────────────────────┘
```

### 5.2 FC_TONE_OFF — 家长行为 tone override（v4.0.16 代码层）

四类关键词扫描，命中则强制 DIAGNOSTIC：

| 类别 | 示例关键词 | 效果 |
|------|-----------|------|
| 催促/打断 | "快点""别说了""闭嘴" | 冻结 tone 灵活覆盖 |
| 评判贴标签 | "你太敏感""你就是不上心" | 禁止切换鼓励式 |
| 命令单向权力 | "我说了算""不许顶嘴" | 强制诊断式 |
| 轻度贬低/否定情绪 | "有什么好哭""小题大做" | 强制诊断式 |

### 5.3 FC_STALE — 跨窗口语义去重（v4.0.16 代码层）

```python
similarity = SequenceMatcher(None, new_popup, old_popup).ratio()
if similarity >= 0.70:
    should_popup = False  # 拒绝，避免复读
```

配置：历史窗口 5 条，阈值 0.70。

### 5.4 P2 — 鼓励式强制 repair phrase（v4.0.14）

正则检测引号内 ≥4 字的话术 `「『"（...）』」"`，缺失时重试一次，仍缺失则弹窗不通过。

### 5.5 周易上下文注入

Stage 1 的分析结果以模板格式注入到 system prompt 头部，LLM 据此查第八节策略速查表：

```
当前沟通状态属于 ☱ 兑（控失失）——释放扩散型。
容器状态：无容器   风险等级：中
分析洞察：开头有规则边界，但很快滑入权力拉锯
```

## 六、v4.0.16 → v4.0.17 变更

### 问题

v4.0.16 的七层结构术语（"多极""在场""反馈真""内生性"等）通过两条路径泄漏到弹窗正文：

```
  ┌─────────────────────────────────────────────┐
  │ 感染路径 1：正向示例（L159）                 │
  │   ✅ 明确鼓励："…这个多极的时刻…"            │
  │   → LLM 学会了在弹窗里用"多极"              │
  ├─────────────────────────────────────────────┤
  │ 感染路径 2：指令要求（L150）                 │
  │   "必须从七层积极信念中选取一个命名"         │
  │   → 强制 LLM 输出术语标签                   │
  ├─────────────────────────────────────────────┤
  │ 感染路径 3：塌陷形态列表（L137）             │
  │   "单极生焦虑""糖锚错位"… 无内部标记         │
  │   → LLM 可能直接引用                        │
  └─────────────────────────────────────────────┘
```

### 修复

| # | 位置 | 旧 | 新 |
|---|------|-----|-----|
| 1 | L150 指令 | 必须从七层积极信念中选取一个命名 | 用日常语言描述，不需要贴七层术语标签（如"多极""在场""内生性"等） |
| 2 | L159 示例 | 这个多极的时刻 | 你放下了'只有一种对'的标准 |
| 3 | L137 列表 | 七层塌陷形态（可选参考）：… | 七层塌陷形态（可选参考，**仅用于内部定位，不得出现在弹窗正文中**）：… |

### 文件变更

```
  system_prompt_v4.0.16.txt → system_prompt_v4.0.17.txt  (rename, 99% 相似)
  realtime/config.yaml                                      (system_prompt_path 更新)
  scripts/adversarial_leakage.py                            (新增：泄漏对抗测试)
  results/adversarial_leakage.json                          (新增：测试结果)
```
