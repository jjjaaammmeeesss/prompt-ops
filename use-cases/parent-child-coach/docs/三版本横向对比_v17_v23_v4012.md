## 2. 各版本核心框架

### 2.1 v1.7 — 初代结构化基线

**设计哲学**：把心理治疗的专业诊断框架（CBT 认知歪曲 + 七层教育哲学）翻译成 AI 可执行的规则，用强制模板确保输出一致性。

**核心框架**：

```
一、本体公理 → 二、盲区二分（思维扭曲 vs 认知盲区）
→ 三、三维视角（情绪 × 动机 × 信念）
→ 四、七层结构（积极信念 + 塌陷形态）
→ 五、6 条生成规则（发心承认 → 模式揭示 → 建议 → 措辞 → 邀请感 → 专一度）
→ 六、输出格式 + 3 项自检
→ 七、12 个专家标注的 few-shot 示范
```

**关键特征**：
- **强制"眼镜"隐喻**：模式揭示必须用 "你正在用……的眼镜在看……" 句式
- **术语不可省略**：必须从 CBT 歪曲类型或七层塌陷形态中选一个命名
- **JSON 结构化输出**：`{should_popup, tone, popup_insight, popup_suggestion}`，带 Step 0 不弹判定
- **14 个 few-shot**：嵌入 User Prompt，覆盖诊断式与鼓励式

---

### 2.2 v2.3 — 极简人本主义版

**设计哲学**：抛弃所有术语、框架名、固定句式，让 AI 像一个 "很懂他的人，在现场轻声提醒"。三位专家 2025 年手工标注。

**核心框架**：

```
你信什么（不可改）
→ 你心里默默做的事（三层内省：情绪/善意/视角宽窄）
→ 类型判断 · 三个容易误判的场景
→ 你怎么说话（两种视角、假设语气、不说术语）
→ 硬规则（—— 功能墙、一句话建议、分段、字数）
```

**关键特征**：
- **`——` 功能墙**：严格区分洞察与建议。墙前 = 全部洞察，墙后 = 一句建议。不可交叉。
- **零术语原则**：不让 AI 套框架名，用大白话描述 "他刚才是怎么想的，还有一面他没看到"
- **三个反直觉场景修正**：表面"爱"实际"退让"→ 诊断；家长已做得很好 → 纯鼓励；孩子对抗实际求救 → 诊断权力结构
- **极短**：整个 prompt 只有 ~4.7 KB，约 v1.7 的 1/16

---

### 2.3 v4.0.12 — 周易八卦集成生产版

**设计哲学**：以 v2.3 为基底，经过 DSPy MIPROv2 自动优化（31 条专家标注）产出初始 v4.0，再经 12 轮手工迭代修复，集成周易三爻八卦策略表，将中国哲学的诊断框架（阴阳/卦象/爻变）与认知行为框架融合。

**演化链**：
```
v2.3 (专家手工)
  ↓ DSPy MIPROv2 (31 examples, baseline 0.838)
v4.0 → v4.0.1 → v4.0.3 → v4.0.4 → v4.0.5 → v4.0.6
  → v4.0.7 → v4.0.8 → v4.0.9 → v4.0.10 → v4.0.11 → v4.0.12
```

**核心框架**：

```
一、本体公理（继承 v1.7）→ 二、盲区二分
→ 三、三维视角 → 四、七层结构
→ 五、弹窗生成规则（6 条，每条均含多个子版本的强化补丁）
    5.1 发心承认 → 5.2 模式揭示（先描述后命名 / 结构>情绪 / 控制→责任交还）
    → 5.3 建议（自然后果 vs 信任试验 / 4 条假交还识别）
    → 5.4 措辞自然度 → 5.5 邀请感（含乾卦危险型例外）
    → 5.6 洞察准确性
→ 六、输出格式 + 多项自检
    6.1 基础 3 项自检（模式/语言/语气）
    6.2 tone 灵活覆盖自检（3 步骤）
    6.3 脑补检查（3 步骤，v4.0.12 扩展到全文）
    6.4 对象错位修复
→ 七、12 个专家 few-shot 示范（继承 v1.7 的示范集）
→ 八、周易三爻八卦弹窗策略速查表（v4.0 新增，9 卦象 × 策略映射）
```

**关键特征（v4.0.x 相比前代的差异化改进）**：

| 改进点 | 版本 | 内容 |
|--------|------|------|
| 模式揭示灵活化 | v4.0.1 | 从强制"眼镜"模板 → 灵活自然表达 |
| 鼓励式精准化 | v4.0.3 | 点出具体动作，禁笼统品质标签 |
| 去术语强制 | v4.0.4 | 先描述后命名，术语可选 |
| 结构 > 情绪 | v4.0.5 | 规则场景优先揭示权力/选择结构 |
| 责任交还框架 | v4.0.6/7 | 控制→责任交还；自然后果 vs 信任试验 |
| tone 灵活覆盖 | v4.0.9/11/12 | ≥2 积极行为 → 自动切鼓励式（含沉重场景特例） |
| 全面禁脑补 | v4.0.10/12 | 禁止编造对话中未出现的家长话语/行为/道具 |
| 八卦集成 | v4.0 | 9 种卦象 → 弹窗策略映射，含乾卦危险型紧急喊停 |

## 4. 优缺点分析

### 4.1 v1.7

**优点**：
- **诊断框架完整**：CBT + 七层结构提供了丰富的诊断词汇和定位工具
- **输出格式规范**：JSON 结构化输出便于后处理和质量监控
- **Few-shot 质量高**：12 个专家标注示范覆盖了典型场景（火山/做饭/离婚/看画/窗台/手机/理发/睡前/过马路/积木/骑车/乐高）
- **"眼镜"隐喻直观**：对 AI 来说，用"端出一副眼镜"作为模式揭示的意象很清晰

**缺点**：
- **自主 tone 判断不稳定**：v1.7 自己判断弹窗类型（diagnostic/empowering），与数据集标注系统性分歧，导致 tone 偏移和漏弹
- **术语堆砌**：强制要求命名 CBT 歪曲或七层塌陷，导致输出像心理教科书而非耳边提醒
- **"眼镜"句式僵化**：每句模式揭示都套 "你正在用……的眼镜在看……"，AI 容易产生模板疲劳
- **庞大且分裂**：System + User 共 ~77KB，User Prompt 3.6 万字，推理成本高
- **短对话漏判**：Step 0 的不弹判定过于保守，118 字短对话三轮全判不弹
- **Variance 偏大**：独立测试 variance 0.083，tone 在 diagnostic/empowering 间跳变

---

### 4.2 v2.3

**优点**：
- **极简，人话感最强**：整篇没有任何术语、框架名、固定句式，输出的弹窗像一个人在耳边说话
- **`——` 功能墙设计精妙**：洞察与建议严格分离，防止 AI 在建议段继续塞洞察（常见退化模式）
- **三个误判场景修正**：对 "表面爱实际退让" / "家长已做得很好" / "对抗实际求救" 三种反直觉场景有明确指导
- **短小精悍**：4.7 KB，成本极低，适合快速通道/高并发场景
- **结构清晰**：每段一个意思——你信什么 → 你怎么想 → 你怎么说 → 你不能做什么

**缺点**：
- **诊断深度不足**：缺少系统性的诊断框架，面对复杂对话（权力争夺、信念僵化、多层误解）时弹窗容易偏浅
- **无 tone 覆盖机制**：数据集标什么就写什么，不会根据对话实际内容灵活调整
- **无脑补防护**：没有禁止编造具体道具/家长话语的规则，AI 可能胡编
- **建议方向单一**：只有一句建议 + 一句可说的话，缺少责任交还/自然后果/信任试验等差异化策略
- **长对话力不从心**：没有 "结构 > 情绪" 的优先级概念，复杂权力场景只停于情绪层
- **独立测试表现差**：12 新用例 0.625，远低于 v4.0.12 的 0.867

---

### 4.3 v4.0.12

**优点**：
- **综合得分最高**：在所有测试集上稳定领先 v1.7 和 v2.3
- **tone 灵活覆盖机制**：系统标注诊断式但家长有 ≥2 积极行为 → 自动切鼓励式，避免 "该鼓励却诊断" 的冷感（包括沉重场景特例如 C5-005 妈妈哭）
- **先描述后命名**：模式揭示的核心原则解决了 v1.7 的术语堆砌问题，同时保留了诊断词汇作为可选工具
- **结构 > 情绪优先级**：规则执行场景下优先揭示权力/选择结构，不只看情绪层——这是 v2.3 完全缺失的维度
- **责任交还框架**：精心设计了自然后果（吃饭/作息）vs 信任试验（手机/约定）两种形态，各有严格约束和反例
- **全面禁脑补**：从 v4.0.10 的 "下次部分禁脑补" 逐步升级到 v4.0.12 的 "全文禁脑补"，包括禁止编造家长话语/行为/具体道具
- **对象错位修复**：弹窗永远对家长说话（"你"），不会在孩子表现好的场景写成对孩子的表扬
- **八卦策略表**：将周易哲学与中国家庭教育场景对应，为生产系统的 Stage 1（卦象分析）→ Stage 2（弹窗生成）提供了接口
- **乾卦危险型紧急喊停**：在对话升级失控时可以突破邀请语气，使用直接刹车语
- **详细的示范集**：继承 v1.7 的 12 个专家 few-shot，质量不变

**缺点**：
- **Prompt 持续膨胀**：从 v4.0.10（55KB）→ v4.0.12（62KB），增长 12.7%。规则层叠可能引入内部矛盾
- **复杂度高**：生成规则 + 自检项 + tone 覆盖规则 + 脑补检查 + 八卦策略，AI 是否真正消化了所有规则存疑
- **仍有残留失败 case**：C5-001（摆碗碎碗）0.463、DS_001（收盘子）0.513，两个 case 在全量校标和独立测试中均 <0.70
- **禁止脑补的矛盾**：v4.0.12 的 "全面禁脑补" 可能过度约束 AI，在需要合理推断的场景也变得保守
- **tone 覆盖门槛粗糙**：≥2 积极行为的硬阈值，可能漏掉只有 1 个高质量积极行为的场景
- **维护成本高**：12 轮迭代累积了大量补丁式规则，未来修改时需仔细排查规则间的交互

## 5. 适用场景

| 场景 | 推荐 | 理由 |
|------|------|------|
| **生产环境（主通道）** | v4.0.12 | 综合得分最高，tone 灵活覆盖减少冷感，禁脑补防止胡编 |
| **高并发快速通道** | v2.3 | 4.7 KB，极低成本，短对话场景下人话感好 |
| **低风险场景（简单提醒/肯定）** | v2.3 | 不需要深层诊断的场景，v2.3 的简洁反而是优势 |
| **规则执行/权力争夺场景** | v4.0.12 | "结构 > 情绪" + 责任交还框架是该场景的核心武器 |
| **家长情绪崩溃/沉重场景** | v4.0.12 | tone 灵活覆盖的沉重场景特例（C5-005）确保不会被冷诊断 |
| **需要最丰富诊断词汇的研究/分析** | v1.7 | CBT + 七层提供了最系统的诊断元语言 |
| **作为回退版本** | v2.3 | 已验证可与 v4.0.12 共存，万一 v4.0.12 出问题可秒切 |
| **教学/Onboarding** | v1.7 | 结构化程度最高，适合新人理解 "弹窗应该怎么做" |

## 6. 演化启示

### 6.1 三条演化主线

```
v1.7 (结构化深度) ─────────────────────────────────────────────┐
  │  强制框架、术语命名、JSON输出                                │
  │  问题：术语堆砌、tone 偏移、模板僵化                          │
  └──→ v1.11 → v1.13（独立路线，仍在迭代）                      │
                                                                │
v2.3 (人本主义极简) ───────────────────────────────────────────┐│
  │  零术语、功能墙、纯人话                                      ││
  │  问题：诊断深度不足、长对话乏力                              ││
  └──→ [被 v4.0.12 取代]                                       ││
                                                                ││
v4.0.12 (融合 + 八卦) ←────────────────────────────────────────┘│
  │  v2.3 基底 + DSPy MIPROv2 + 12 轮手工迭代 + 周易八卦          │
  │  继承 v1.7 的诊断框架和 few-shot，采纳 v2.3 的人话要求         │
  │  问题：Prompt 膨胀、规则层叠                                  │
  └──→ 待观察：是否需要 v4.0.13 精简化                           │
```

### 6.2 关键教训

1. **结构化与自然度不是二选一**：v4.0.12 证明了可以同时有深层诊断框架和自然人话表达——关键是 "先描述后命名"，让术语退居为工具而非枷锁。
2. **极简有天花板**：v2.3 的 4.7 KB 在某些场景下是优美的，但在复杂权力场景下无力深入。弹窗的质量上限受 prompt 的诊断深度约束。
3. **迭代累积的代价**：12 轮手工修复的补丁式增长，让 v4.0.12 成了 62KB 的怪兽。下一步可能不是再加规则，而是剪枝重构。
4. **tone 判断不应交给模型**：v1.7 的自主 tone 判断是最大的方差来源；v4.0.12 用 "数据集强制 + 灵活覆盖" 的两层机制解决了这个问题。
