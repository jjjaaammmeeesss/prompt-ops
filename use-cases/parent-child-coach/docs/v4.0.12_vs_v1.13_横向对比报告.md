# v4.0.12 vs v1.13 · 横向对比报告

> 生成时间：2026-07-29
> 对比目的：理清两套 prompt 的架构差异、方法论取舍、各自强弱项，为下一步融合/选择提供依据

---

## 一、一句话定位

| | v4.0.12 | v1.13 |
|---|---|---|
| 定位 | 当前**生产版本**，已上线 | **候选版**，从未上线 |
| 基底 | v2.3 专家手工 + DSPy MIPROv2 自动优化 | v1.12 迭代修复 |
| 迭代轮数 | 12 轮手工修复（v4.0.1→v4.0.12） | 1 轮修复（v1.12→v1.13），四项变更 |
| 实测数据 | 丰富（70 全量 0.954 / 12 独立 0.867 / 50 盲测 0.947） | 仅对抗测试（19:19 TIE vs v1.12） |

## 二、架构差异

| 维度 | v4.0.12 | v1.13 |
|---|---|---|
| **Prompt 结构** | 单 System Prompt（1,130 行） | System Prompt（~200 行）+ User Prompt（~1,400 行） |
| **预处理** | 外部 Stage 1：周易三爻分析器 → 卦象上下文注入 Stage 2 | 无外部预处理，全部在一个 LLM 调用内完成 |
| **输出格式** | 自由文本弹窗（无 JSON schema 约束） | 严格 JSON（含完整诊断中间产物：layer0→step1→child_state→popup） |
| **模型调用** | 两次（Stage 1 cheap model + Stage 2 prompt） | 一次（System+User 单次调用） |
| **推理深度** | Stage 1 做结构分析 → Stage 2 做文本生成 | 内部 Step 0→3 自包含推理链 |
| **tone 判定** | 外部数据集强制指定 tone + prompt 内灵活覆盖规则 | LLM 自主判定 tone（基于信念开合） |

### 架构取舍

- **v4.0.12 的优势**：两阶段分离让结构分析（卦象）和文本生成解耦，Stage 1 可以用更便宜的模型，Stage 2 只需做"翻译"
- **v1.13 的优势**：单次调用、内部推理链完整可追溯（JSON 中间产物全部保留），调试友好
- **v4.0.12 的代价**：依赖外部 Stage 1 质量，Stage 1 出错 → Stage 2 被带偏
- **v1.13 的代价**：单次调用承载全部推理负担，长指令遵循度存疑（v1.12 的 P0++ 写前清单形同虚设就是证据）

## 三、方法论层对比

### 3.1 共享根基（两者相同）

| 模块 | 内容 |
|---|---|
| 本体公理（孩子） | 孩子是独立生命，不是父母的作品 |
| 本体公理（家长） | 家长也是完整的人，系统永远先看见家长 |
| 盲区二分 | 思维扭曲 vs 认知盲区，可共存 |
| 三维六格 | 情绪（原生/表层）× 动机（指向孩子/自己）× 信念（打开/收缩） |
| 七层结构 | 反馈真/多极/在场/内生性/双向/关系根/真实学习 |

### 3.2 方法论差异

| 维度 | v4.0.12 | v1.13 |
|---|---|---|
| **双根并立** | 未显式提及 | 显式列出（关系根·二人为仁 + 生命根·真实是老师） |
| **第一性原理** | "醒悟 = 用来看的被看见了 / 阴阳并置" | "醒悟感第一性原理"（引用 soul v2 文档） |
| **周易八卦** | ✅ 独有——九卦象 × 弹窗策略速查表 | ❌ 无 |
| **责任交还框架** | ✅ 独有——控制→责任交还，自然后果 vs 信任试验 | ❌ 无（在建议句中隐含但未结构化） |
| **反话检测** | 未显式处理 | ✅ P6 三条检测规则 + 强制响应规则 |
| **完美对话判定** | 仅 tone 灵活覆盖（≥2 积极行为） | ✅ 七层积极信念映射，≥3 条→纯鼓励/不弹 |
| **修复感知** | 未显式处理 | ✅ 退出条件：道歉/示好/接纳 → 不诊断修复中的人 |

## 四、弹窗生成流对比

### v4.0.12 生成流
```
外部 tone 标注 + 周易卦象上下文
  → 信念维度判定（收缩→诊断 / 打开→鼓励）
  → 发心承认（始终最先）
  → 模式揭示（先描述后命名 / 结构>情绪 / 控制→责任交还）
  → 建议句（与模式揭示锁死）
  → tone 灵活覆盖自检（≥2 积极行为？→ 切换鼓励式）
  → 脑补检查（逐句对照原文）
  → 输出自由文本弹窗
```

### v1.13 生成流
```
对话输入
  → Step 0: 触发判定（不弹/鼓励/诊断三分流）
  → Step 0.5: 诊断必要性判定（三项分流：情绪已接住？孩子自主？无条件接纳？）
  → Step 1A: 三维六格扫描 → layer0
  → Step 1B: 孩子三维扫描 + 反话检测
  → [分流] 诊断式 → Step 2A: 双重扫描(CBT+七层) → 基本遮蔽面 → 深度自检(L1/L2/L3) → 写稿
  → [分流] 鼓励式 → Step 2B: 七层闪光目录 → 纯闪光写稿
  → Step 3: 出门体检（逐句原文锚定 → 眼镜指向 → 反爹味16条）
  → 输出严格 JSON
```

### 关键差异

| | v4.0.12 | v1.13 |
|---|---|---|
| 触发判定 | tone 外部给定 + prompt 内灵活覆盖 | LLM 自主判定，Step 0 + 0.5 两道分流 |
| 深度控制 | 无显式层级要求 | L1/L2/L3 三层深度标尺，诊断必须 ≥L2 |
| 反幻觉机制 | 规则约束（禁脑补动机/建议/家长话语/行为） | 结构性阻断（写后逐句标注原文引用 → 标不出就删） |
| 质量检查 | 三项自检（模式揭示/语言/邀请感）+ tone + 脑补 | 出门体检（逐句锚定 + 眼镜指向 + 反爹味 16 条） |

## 五、创新点交叉对比

### v4.0.12 独有创新

| 创新 | 说明 | 效果 |
|---|---|---|
| **周易八卦体系** | 九卦象 × 三爻分析 × 弹窗策略映射 | 提供结构化的"先验"——在生成前就知道这是什么类型的对话 |
| **tone 灵活覆盖** | ≥2 积极行为 → 诊断式自动切换鼓励式 | 修复了"标注诊断式但家长其实做得不错"的误判 |
| **责任交还框架** | 控制→责任交还，自然后果（承受真实不适）vs 信任试验（有边界可验证） | 把建议句从"优化控制"升级为"交还主体性" |
| **全面禁止脑补** | 扩展到弹窗所有部分，不只是"下次"段 | v4.0.12 仍在 C5-001/DS_001 上偶发脑补 |

### v1.13 独有创新

| 创新 | 说明 | 预期效果 |
|---|---|---|
| **F4 前置分流** | Step 0.5 三项判定——在启动诊断前先判断是否真的需要诊断 | 减少对正常对话的过度干预 |
| **F1 P0++ 逐句原文锚定** | 写后逐句标注原文引用 → 标注不出的句子整句删除 | 结构性阻断虚构——LLM 无法在核查阶段蒙混过关 |
| **F2 P6 反话强制响应** | ≥2 条反话信号 → 禁止赞美/禁止翻译/禁止软化，必须指出防御机制 | 修复半吊子反话识别——识别后切换到"防御模式" |
| **F3 P7 深度自检三步** | 重复扫描/话外之话/矛盾扫描，至少命中一项方可写稿 | 防止 L1 表面诊断——强制至少到 L2 结构层 |
| **完美对话判定** | 七层积极信念映射，≥3 条 → 纯鼓励/不弹，禁止诊断 | 防止对高功能家长过度干预 |
| **避重硬约束** | 同案上下文追踪已弹洞察，防止重复照同一副眼镜 | 多窗口场景下保持诊断多样性 |

## 八、总体评价

### v4.0.12
**强在生产验证。** 经过 12 轮迭代 + 大量测试数据支撑，在已知场景上表现稳定（校标 0.954）。架构简洁（单 prompt + Stage 1 预处理），tone 处理灵活。核心短板是**反幻觉机制靠规则约束而非结构阻断**——v4.0.12 的三次脑补修复（v4.0.10 → v4.0.11 → v4.0.12）每次都只扩展禁止范围，没有改变"写了一句话→再检查是否违规"的基本范式。

### v1.13
**强在设计思路。** F1（逐句锚定）/F2（反话响应）/F3（三步深度自检）/F4（前置分流）四项修复的方向都是正确的——它们不是"更严的规则"而是"不同的做法"。核心短板是**从未生产验证**——不知道 LLM 能否在实际调用中忠实执行这些复杂指令（v1.12 的教训是 LLM 会读指令然后按语言概率生成，不会真正执行检查流程）。

### 一句话
**v4.0.12 是工程上更成熟的版本，v1.13 是设计上更激进的版本。** 最务实的下一步：把 v1.13 的 F1（逐句原文锚定）和 F2（反话强制响应）移植到 v4.0.12 框架中，用 v4.0.12 的测试基础设施验证效果。
