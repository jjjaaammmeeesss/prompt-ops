# 四版本对比 · 完整测试记录

> **日期**：2026-07-28 ~ 2026-07-29
> **目标**：对比 v1.11 / v4.0.12 / v2.3 / v1.7，确定哪个版本最优
> **脚本**：`scripts/compare_four_versions.py`
> **外层监控**：`OuterLoopMonitor`（排名稳定性 + 分数漂移 + 收敛判断）

---

## 一、测试背景

### 1.1 为什么做这个对比

v1.11 是 A 轨最新候选版（基于 v1.10 + P0/P3/P5 微调），通过了 Gate1/Gate4 验证（10:8 vs v1.7，55.6% WEAK_PASS）。需要跟当前生产版 v4.0.12 以及上一代基线 v2.3、v1.7 做公平横向对比，确认是否值得替换生产版本。

### 1.2 四个版本简介

| 版本 | 路线 | 架构 | 字数 | 状态 |
|------|------|------|------|------|
| **v1.11** | A 轨候选版 | System Prompt + User Prompt（14 few-shot）+ JSON 输出（popup_insight/popup_suggestion） | System 1924 + User 36888 | ⚠️ WEAK_PASS vs v1.7 |
| **v4.0.12** | A 轨生产版 | 单体 System Prompt + 卦象系统 + 纯文本输出 | 23320 | 🟢 当前生产 |
| **v2.3** | 专家手工版 | 简单 System Prompt + 纯文本输出 | 1707 | 🔵 上一代生产/回退保留 |
| **v1.7** | A 轨原始版 | 单体 System Prompt + 纯文本输出 | 1924 | 🔴 保留待验证 |

版本族谱：
```
v1.7 (原始A轨)
  ├─ v1.9 → v1.10 → v1.11 (候选版)
  └─ v2.3 (专家基线) → DSPy MIPROv2 → v4.0 → ... → v4.0.12 (生产)
```

### 1.3 快速通道说明

四个版本均可在生产环境中配备 `KeywordTrigger` 快通道（关键词/正则/连续否定检测），这是 prompt 无关的基础设施层。**快速通道不是版本差异点，对比聚焦在 prompt 本身的诊断质量上。**

## 三、测试方法

### 3.1 生成配置

| 参数 | 值 |
|------|-----|
| 生成模型 | DeepSeek V4 (`deepseek-chat`) |
| API | `api.deepseek.com` |
| Temperature | 0.3 |
| Max tokens | v1.11: 1024, 其他: 400 |
| 输出格式 | v1.11: JSON（popup_insight + popup_suggestion），其他: 纯文本 |

### 3.2 Judge 配置

| 参数 | 值 |
|------|-----|
| Judge 模型 | Claude Opus 4.7 (`claude-opus-4-7`) |
| API | `luanapi.xingluan.cn/v1`（星鸾代理） |
| Metric | `LLMJudgeMetric` v3.0 |
| 维度权重 | strategy_alignment=0.30, dialogue_fidelity=0.20, tone_alignment=0.20, natural_language=0.15, core_insight=0.15 |
| 一票否决 | 事实错误 / tone 误判 → 直接 0 分 |
| 通过阈值 | weighted_score ≥ 0.70 |

### 3.3 公平性保证

- **同数据集**：四个版本用完全相同的 12 个独立用例
- **同 Judge**：同一个 Claude Opus 4.7 实例 + 同一套 metric
- **同生成模型**：全部用 DeepSeek V4
- **无快通道差异**：对比测试不包含 KeywordTrigger 层
- **v1.11 特殊处理**：解析 JSON 输出，诊断式用 `insight + —— + suggestion` 拼接，鼓励式只用 insight

### 3.4 外层监控（新增）

本次测试在 `compare_four_versions.py` 中新增了 `OuterLoopMonitor`，每轮后自动检测：

1. **排名稳定性**：winner 是否连续 N 轮一致
2. **分数漂移**：任一版本 vs 前一轮下降 > 0.08
3. **收敛判断**：排名稳定 + 分数波动 < 0.02

三种提前终止规则：
- 收敛 → 目标达成
- 连续 2 轮分数漂移 → Judge/模型可能不稳定
- 同一 winner 连续 4 轮 → 压倒性优势

### 4.4 关键发现

1. **v4.0.12 是无可争议的最优版本**：
   - n=12 均分 0.628，领先第二名 22%
   - n=3 均分 0.750，三轮全部排名第一
   - 唯一拥有卦象系统快速通道的 prompt（乾卦危险型直接喊停）

2. **v1.11 是合格的第二名，但不足以替换 v4.0.12**：
   - n=12 均分 0.513，落后 v4.0.12 约 0.115
   - 优势：在对话较短的事实类 case 上表现好（C10-003/006/008 全部 ≥0.788）
   - 劣势：C5 系列（盲区补充用例）多次拿 0 分（C5-001, C5-005）
   - v1.11 的 14 个 few-shot 带来了短对话场景的优势，但对长对话/盲区场景覆盖不足

3. **v2.3 和 v1.7 已确认劣于 v4.0.12**：
   - v2.3：均分 0.459，仅 1707 字的简短 prompt 缺乏领域深度
   - v1.7：均分 0.428，n=3 中呈现持续下滑趋势（0.450→0.362→0.242）
   - v1.7 之前的记忆中说"现有对比证据不足以宣告劣于 v4.0.12"——本次测试可以更新这个结论了

4. **硬骨头 case**：
   - C10-004 和 C5-001 四个版本全部不及格，属于 judge/dataset/model 层面的系统性难题，不是 prompt 能解决的

## 七、结论

1. **🥇 v4.0.12 是最优版本**，在所有测试配置下均排名第一，建议继续作为生产版本
2. **🥈 v1.11 是合格的 A 轨候选版**，在短对话事实类 case 上有竞争力，但在盲区覆盖上不及 v4.0.12
3. **v2.3 和 v1.7 已确认劣于 v4.0.12**，v1.7 的"保留待验证"状态可以更新为"已确认劣于生产版"
4. **外层监控机制验证通过**，后续对比测试可复用 `--outer-loop` 模式
5. **快速通道（KeywordTrigger）是基础设施层**，四个版本均可配备，不影响 prompt 对比结论
