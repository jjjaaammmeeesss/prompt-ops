## 五、两个版本的典型失败模式

### v1.13 典型失败

1. **Veto 级事实错误**（约 10% 案例双零以外 v1.13 独零）：F1 逐句锚定没有完全解决虚构问题——LLM 在长指令下仍会跳过核查步骤
2. **Tone 误判**（53% 判定为 empowering）：在标注为"诊断式"的案例中，v1.13 过度切换到鼓励式——F4 前置分流可能把"家长接住了部分情绪"误读为"不需要诊断"
3. **Skip 漏弹**（2 例）：该弹却判定为不弹——前置分流的阈值可能偏高

### v4.0.12 典型失败

1. **Veto 级事实错误**（约 10% 独立 veto + 7% 双零中 v4.0.12 侧）：禁脑补规则作为文本约束，LLM 不总是遵守
2. **脑补家长话语**（C5-001/DS_001 等已知问题重现）：v4.0.12 在特定场景仍然虚构了对话中不存在的家长话语

## 六、上线决策

### 决策矩阵

| 门1 结果 | 门4 结果 | → 裁决 |
|----------|----------|--------|
| TIE | TIE | **保持 v4.0.12**（生产稳定优先），v1.13 修复点移植到 v4.0.13 |

### 裁决理由

1. **生产稳定性**：v4.0.12 经过 12 轮迭代 + 大量实测验证，已知边界和已知问题清楚
2. **统计结果**：两个门的 CI 都跨零，无证据表明 v1.13 更优
3. **v1.13 实证状态**：从未生产验证，四项修复的设计方向正确但实施效果未达预期
4. **边际递减**：v1.13 的四项修复在 v1.12 → v1.13 上只产生了 19:19 TIE（对抗测试），在本次校标测试上也未展示显著改进

### 建议的 v4.0.13 迭代方向

| 优先级 | 借鉴 | 理由 |
|:--:|------|------|
| 🔴 高 | **F1 逐句原文锚定** | v4.0.12 的禁脑补是规则约束（LLM 可绕过），v1.13 的锚定是结构性阻断。需适配到单 prompt + 自由文本输出的架构中 |
| 🔴 高 | **F2 反话强制响应** | v4.0.12 目前没有反话处理机制，ADV-07/08 类场景是盲区 |
| 🟡 中 | **F4 前置分流** | 减少对正常/修复中对话的误弹窗——但需要更精准的阈值，避免 v1.13 的 53% empowering 问题 |
| 🟡 中 | **F3 三步深度自检** | 提供具体的发现方法，而非只标签"L2 以上"——但需要简化为 v4.0.12 架构能承载的形式 |

## 七、方法论文本

### 本次测试的限制

1. **仅 1 轮**：variance 未被充分控制。3 轮可能让 CI 收窄并显示显著差异
2. **Judge 的 10% 双零率**：约 7/70 案例双方都被 veto，这些案例可能是校标本身有问题（格式不标准或包含额外标注文字触发 judge 误判），也可能是两个版本都犯了事实错误
3. **Blind A/B 75% TIE**：GLM-5.2 作为盲评裁判区分力不足，可能因为两个版本的输出风格差异不够大
4. **Judge-人相关性已知极弱（r=0.021）**：跨版本的相对排序仍然有效，但绝对分数不能替代人类判断

### 两个版本的架构差异回顾

| | v1.13 | v4.0.12 |
|---|---|---|
| Prompt 行数 | 1,614 行 | 1,130 行 |
| 架构 | System + User 双 prompt | 单 System Prompt + 周易 Stage 1 |
| 输出格式 | 严格 JSON（含诊断中间产物） | 自由文本弹窗 |
| 推理检查 | F1/F2/F3/F4 四道结构性阻断 | 三项自检 + tone 覆盖 + 脑补检查 |
| 生产验证 | ❌ 从未上线 | ✅ 12 轮迭代 + 大量实测 |
