# v4.0.x 周易八卦弹窗系统 · 系统梳理

> 生成时间：2026-07-20 | 当前生产版本：v4.0.12

## 1. 架构全景

### 1.1 两阶段流水线

```
实时对话流 → Stage 1: 周爻分析器 → Stage 2: 弹窗生成器 → 弹窗输出
              (fast/cheap model)    (v4.0.x system prompt)
              deepseek-chat         deepseek-chat
              256 tokens            640 tokens
```

**Stage 1**（`realtime/zhouyi_prompts.py`）：分析当前对话中家长的三爻状态（下/中/上爻各为"控"或"失"），结合容器判定（有容器/无容器），映射到八卦卦象，输出置信度和建议 tone 类型。

**Stage 2**（`system_prompt_v4.0.x.txt`）：接收卦象分析结果，生成最终弹窗文本。核心 prompt 文件——v4.0.x 的所有版本迭代都发生在这里。

### 1.2 周易卦象体系

九种卦象 × 对应的弹窗策略：

| 卦象 | 三爻 | primary_tone | 策略关键词 |
|------|------|-------------|-----------|
| 坤 | 控控控 | 鼓励式 | 全程稳定承载，轻问是否有压抑 |
| 震 | 控失控 | 鼓励式 | 前面安全→最后真实冒出，肯定"敢" |
| 坎 | 控失控 | 鼓励式 | 中间冲突→最后修复，肯定关系弹性 |
| 巽 | 失失控 | 鼓励式 | 前面混乱→最后沉淀出理解 |
| 艮 | 失控控 | 鼓励式 | 先乱后定，肯定"暂停"能力 |
| 兑 | 控失失 | 诊断式 | 情绪闸门打开，帮能量收束到具体动作 |
| 离 | 失控失 | 诊断式 | 被看见但没落地，指向"反复"模式 |
| 乾（安全型）| 失失失+有容器 | 鼓励式 | 疯玩脑洞，关系底盘稳 |
| 乾（危险型）| 失失失+无容器 | 诊断式 | 全程压迫升级，最高紧急度，直接喊停 |

### 1.3 弹窗双模式

| 模式 | 字数 | 使用场景 |
|------|------|----------|
| 诊断式 | 100-200字 | 家长信念收缩、有盲区 |
| 鼓励式 | 30-60字 | 家长视角打开、已经做到值得肯定 |

## 2. v4.0.x 版本演化链

### 2.1 起源

v4.0.x 以 **v2.3**（三位专家 2025 年手工标注的 system_prompt.txt）为基底，经过 DSPy MIPROv2 自动优化（31 条专家标注数据，24 train + 6 val），产出初始 v4.0。之后进入手工迭代修复，每个小版本修复上一版本暴露的具体失败案例。

### 2.2 版本时间线

```
v2.3 (stable, 专家手工)
  ↓ DSPy MIPROv2 (31 examples, baseline 0.838)
v4.0  → v4.0.1 → v4.0.3 → v4.0.4 → v4.0.5 → v4.0.6
  → v4.0.7 → v4.0.8 → v4.0.9 → v4.0.10 → v4.0.11 → v4.0.12 ← 当前生产
```

（v4.0.2 无记录/未产生）

### 2.3 逐版变更

| 版本 | 修复目标 | 变更内容 | 触发 case |
|------|----------|----------|-----------|
| **v4.0.1** | 表达僵化 | 模式揭示从强制"眼镜"模板改为灵活自然表达 | 全量 |
| **v4.0.3** | 鼓励空泛 | 鼓励式弹窗点出具体动作，禁用笼统品质标签（如"在场"） | 全量 |
| **v4.0.4** | 术语堆砌 | 诊断式不再强制 CBT/七层术语命名，先描述后命名 | 全量 |
| **v4.0.5** | 只看情绪不看结构 | 规则执行场景增加"结构 > 情绪"优先级 | 规则类场景 |
| **v4.0.6** | 控制式建议 | 建议方向从"守稳规则/参与定规则"→"责任交还"框架 | 控制类场景 |
| **v4.0.7** | 假责任交还 | 精化约束：自然后果承受真实不适、信任试验有边界+可验证、4 条假交还识别规则、场景分化 | 责任交还类 |
| **v4.0.8** | 术语滥用 | 去掉"读心术的眼镜"前缀（AI 直接复制）、自检从"给名称"→"描述动态"、加"术语不能独自出场"反例 | 术语类 |
| **v4.0.9** | 双盲区 | ① tone 灵活覆盖（≥2 积极行为→自动切鼓励式）；② 对象错位修复（弹窗永远对家长，不直接对孩子） | 全量校标 |
| **v4.0.10** | 脑补建议 | 禁止在"下次"部分编造对话中未出现的具体道具/方法 | C5-001（摆碗碎碗）|
| **v4.0.11** | tone 假覆盖 | 强化 tone 灵活覆盖：30-60 字肯定是完整段落不是前缀；禁套话；加自检项 | case4_w甲（叹气/洗衣机）|
| **v4.0.12** | 脑补家长话语 | 禁止脑补规则扩展到弹窗**所有部分**（不限于"下次"）；加"只描述对话已有内容"原则；强化 tone 覆盖触发判定 | DS_001（收盘子）+ C5-001 |

## 4. 核心 prompt 结构（v4.0.12）

```
一、不可动摇的根基 — 本体公理（孩子/家长）、镜子使命、第一性原理
二、诊断框架 — 盲区二分（思维扭曲 vs 认知盲区）
三、三维视角 — 情绪（原生/表层）× 动机（指向孩子/自己）× 信念（打开/收缩）
四、七层结构 — 积极信念（鼓励式素材）+ 塌陷形态（诊断式定位）
五、弹窗生成规则 — 发心承认 → 模式揭示 → 建议方向 → 自检清单
    5.1 禁止脑补动机
    5.2 术语不能独自出场
    5.3 禁止脑补建议方案（v4.0.10）
    5.4 全面禁止脑补（v4.0.12）
    5.5 tone 灵活覆盖规则（v4.0.9 + v4.0.11）
    5.6 对象错位修复（v4.0.9）
六、弹窗输出格式 — ± 正反例对比
七、自检清单 — 发心/模式/建议/结构/脑补/tone/对象 × 7 项
八、周易三爻八卦弹窗策略速查表 — 9 卦象 × primary_tone × guidance
```

### 关键设计模式

**模式揭示的核心原则**：
1. 先描述具体动态，后（可选）术语点睛
2. 结构 > 情绪（规则场景优先揭示权力/选择结构）
3. 只能描述对话中实际说出口的话和实际发生的行为
4. 禁止编造家长/孩子未说过的话、未做的事

**tone 灵活覆盖**（v4.0.9/11/12）：
- 系统标注 tone=诊断式，但对话中家长有 ≥2 个积极行为 → 自动切换为鼓励式
- 鼓励式 30-60 字是**完整段落**，不是诊断式前加 15 字肯定前缀

## 6. 已知问题与欠账

### 6.1 残留失败 case（v4.0.12 L5 仍 <0.70）

| Case ID | 场景 | 分数 | 根因 |
|---------|------|------|------|
| C5-001 / case_6 | 摆碗碎碗 | ~0.463 | v4.0.12 偶发脑补"你今天帮妈妈摆碗"的具体细节 |
| DS_001 / case_11 | 收盘子 | ~0.513 | miss 金标核心洞察"你全程在教" |
| case_2 | 妈妈累/看画 | 0.625 | 弹窗偏长，落点与专家一致但结构不够紧凑 |
| case_7 | 吃饭/积木 | 0.625 | 偶尔过度聚焦"你不相信我"而 miss 规则结构分析 |

### 6.2 结构性局限

1. **禁止脑补的矛盾**：v4.0.12 加强的"全面禁脑补"规则可能过度约束，使 AI 在需要合理推断的场景也变得过于保守
2. **tone 覆盖的门槛**（≥2 积极行为）：判决较粗，可能漏掉只有 1 个高质量积极行为的场景
3. **prompt 尺寸持续膨胀**：v4.0.10 → v4.0.12 增长 7.1%，规则层叠可能引入矛盾
4. **judge 自身 variance**：同一 case 同版本跑 3 轮得分可差 0.5+，需要运行 3 轮取均值
