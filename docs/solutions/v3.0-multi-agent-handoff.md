## 2. 架构

三层流水线，每窗口一次完整调用链：

```
PerceptionAgent (感知层)
  读 300 字对话 → 五维洞察(情绪/信念/孩子/关系/积极时刻)
    │
    ▼
MasterAgent (总控)
  双路线竞争印证(路线A原文直觉 + 路线B感知分析)
  → 故事弧线 + 主要矛盾 + 弹窗方向(tone)
    │
    ▼
ProductionAgent (生产层)
  基于方向+矛盾+感知 → 写弹窗正文 + 最终 tone
```

**关键事实**：orchestrator 用 `draft.tone`（生产层输出）作为最终 tone，不是总控的 `direction`。所以生产层默认覆盖总控的 tone 判断。但在实践中生产层几乎总是跟从总控的方向，因为它的 prompt 说"方向已经由总控决定了"。

## 3. 评估体系

### 数据集
- 黄金数据集：59 案例，128 窗口，专家标注
- 评估用案例（当前 12 个）定义在 `auto_evolve/optimizer.py` 的 `EVAL_CASES`

### 四项指标
| 指标 | 权重 | 含义 | 判定方式 |
|------|------|------|---------|
| M1 触发准确率 | 25% | 该弹/不该弹 | 确定性匹配 |
| M5 口吻匹配 | 15% | tone 是否与专家一致 | 确定性匹配 |
| M6 洞察质量 | 35% | 弹窗是否抓住了矛盾 | LLM judge |
| M7 安全性 | 25% | 弹窗是否安全/不指责 | LLM judge |

综合分 = 0.25×M1 + 0.15×M5 + 0.35×(M6/5) + 0.25×(M7/5)

### Keep/Discard 规则
- 综合分提升 > 0.3%
- 无单案例 M6 退化 > 15%
- 无 M5 从匹配退化为不匹配
- 无 M7 退化 > 0.5

## 7. 核心发现

1. **感知层预分类是唯一有效的改进**——把"从文本推断家长内在状态"从总控（推理能力弱）转移到感知层（专门做分析），总控只需要查表

2. **M5 tone 分类在 DeepSeek Chat 上本质不稳定**——同一 prompt、同一输入、相邻两次运行，tone 不一致的案例有 5-6/12。不是 prompt 问题，是模型在这个主观判断任务上的能力边界

3. **LLM 变异器基本无效**（~90% 失败率）——因为变异器和被优化对象用同一个模型，它没有能力诊断"为什么判错"

4. **所有生产层 tone 覆盖尝试都毁灭性退步**——生产层写弹窗时自主判断 tone 反而把总控的正确判断改错

## 8. 当前阻塞

M5 口吻匹配卡在 ~47%（12案例均值），波动 ~5%。12 个案例中：
- 5 个始终正确（C10-001/003/004/006, C11-004）
- 5 个始终错误（C10-002/005/008, C11-006/009）
- 2 个不稳定（C11-001, C11-010）

始终错误的 5 个分为两类：
- **假 empowering**（C10-002/005/008）：感知层把表面妥协误判为真实转变
- **假 diagnostic**（C11-006/009）：感知层未识别伤痛回避

都是感知层分类不准导致的连锁反应。
