## 两条路线的关系

```
路线 A（单智能体）          路线 B（多智能体）
─────────────────────      ─────────────────────
v1.7 ──→ v2.3 ──→ v4.0.12    星灵多智能体 v3.1
  ↑ 保留     ↑ 归档  ↑ 生产      ↑ 迭代停滞
```

- 路线 A = 当前生产系统。一个 prompt 完成所有推理。
- 路线 B = 架构实验。分层解耦 + 规则引擎，理论更可控但 tone 受规则硬编码限制。
- 两条路线共享评估框架（M1/M5/M6/M7），但不共享 prompt。
- v1.7 和 v4.0.12 的最终胜负待 n≥27 对比。

## 版本号规则

1. 路线 A：一个文件 = 一个版本号（文件名 = 内部标题版本号），如 `system_prompt_v4.0.12.txt`
2. 路线 B：三层共享一个版本号，不存在内部分层版本号。升级时三层同步，版本号一致才算系统版本 N
3. 留存策略：生产在用 + 上一稳定版保留，中间版本清理（CLAUDE.md 规则 4）
4. v1.7 不得标记为"已淘汰"，需更大样本量对比才能定论
5. 跨路线对比必须同 judge、同 case、同 n
